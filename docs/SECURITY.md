# Безопасность и ограничения

AWG Chain Installer выполняет команды от имени root на **двух принадлежащих вам VPS**. Используйте только доверенные сборки, проверяйте SSH-отпечатки по консоли провайдера и делайте снапшоты до установки.

## SSH и ключи

В первой версии вход по SSH — root с паролем; пароль не сохраняется на диск или в журнал. Отпечаток SSH-ключа сохраняется в локальном `known_hosts`, неожиданное изменение блокирует подключение.

Ключи пользовательских VPN-соединений выдаёт официальная Amnezia VPN. GUI больше **не генерирует собственный Keenetic `.conf`**. Приватный ключ сервера хранится внутри Docker-контейнера `amnezia-awg2`. Межсерверные ключи записываются в `/etc/amnezia/amneziawg/` на обоих VPS с правами `0600`.

## Установка

- Только два **чистых** Ubuntu 24.04 LTS, x86_64, ядро Linux 6.8, публичные IPv4/IPv6; SSH root.
- Нативный AmneziaWG 3.1 на `awg-mediator` и `awg-destination` компилируется из официальных исходников по закреплённым коммитам, а Dockerfile/`start.sh` из исходников клиента Amnezia по коммиту `ac175c8a8147cfe56f98c8372ec17ea2ba00bb02`. Используемый базовый Docker-образ `amneziavpn/amneziawg-go:latest` **пока не закреплён digest**. Его содержимое теоретически может измениться без изменения нашего исходного кода.
- Входной сервер: Docker-контейнер `amnezia-awg2` (UDP 55424), PBR `fwmark 0x6601` / таблица `100`, `DOCKER-USER` kill switch, отдельный служебный UDP-маршрут Docker через таблицу `101`.
- Выходной сервер: AWG UDP 51820 через IPv6 и NAT IPv4.
- Клиентская, межсерверная и две Docker-подсети выбираются как единый профиль. По умолчанию: `10.8.1.0/24`, `10.77.77.0/30`, `172.28.66.0/24`, `172.29.172.0/24`.
- Включается IPv4 forwarding, создаются persistent systemd/awg-quick службы. Автоматического полного отката ещё нет: после ошибки установка может оставить частично изменённые сетевые правила и сервисы.
- Установщик прерывается при конфликтах, UFW, занятых портах/сетях и не перезаписывает обнаруженный managed-контейнер или существующие VPN-профили.

## Выбор сетевых профилей

v0.3 предоставляет выпадающий список нескольких готовых наборов и ручной ввод четырёх частных IPv4 CIDR (/24 и /30). Установщик проверяет канонические адреса, запрет публичных подсетей и внутренние пересечения, затем перед изменением системы проверяет IP-маршруты, адреса интерфейсов и диапазоны Docker IPAM **на обоих VPS**. Но GUI не способен увидеть домашние подсети пользователя/друзей и сети за маршрутизаторами — эти конфликты остаются ответственностью владельца.

Подмена сети поддерживается только в сценарии **чистой установки**. Выполнить миграцию уже существующих пользователей Amnezia на другую адресацию без пересоздания конфигураций нельзя одним выбором в GUI; автоматическая миграция не реализована.

## Проверки

Прототип CLI уже протестирован на реальных двух VPS: официальный клиент обнаружил managed-контейнер, создал peers, независимые пользователи подключились, внешний IP контейнера был адресом выходного VPS. Docker-рестарт и полный reboot сохранили PBR и служебный UDP-маршрут. GUI v0.3.1 переносит эти сценарии, но установка с альтернативными подсетями **ещё не проверена на реальных VPS**.

На вкладке «Amnezia VPN» производится read-only диагностика, включая проверку наличия выделенной сети Docker, таблицы `101`, PBR и времён DNS/TCP/TLS/TTFB из контейнера. Эти проверки не изменяют сервер.

**Отдельная опция оптимизации MSS** выполняет сетевую модификацию только после подтверждения пользователя. Она ограничивает MSS до 1160 байт для новых TCP-соединений в двух направлениях между `awc0` и `awg-mediator` при MTU межсерверного туннеля 1200. Изменяется только `/usr/local/sbin/awg-chain-managed-route` и соответствующие правила `mangle/FORWARD`. Ключи, интерфейсы, Docker и DNS не изменяются и не перезапускаются. На установках с другой топологией или MTU изменение отклоняется. Повторный запуск не добавляет дублирующих правил. Хотя изменение локальное, рекомендуется сохранить снапшот VPS, а эффективность оценить сравнением замеров до/после: если задержка вызвана DNS, эта опция не поможет.

## Важное ограничение: обновления Amnezia

**Автоматическая миграция или пересоздание контейнера Amnezia не поддержаны.** Если официальный клиент пересоздаст Docker-контейнер, он может изменить опубликованный IP/сетевые интерфейсы или переписать `start.sh`; тогда правила PBR и kill switch перестанут соответствовать фактическому состоянию. Не считайте сетевую изоляцию гарантированной сразу после такого обновления. До обновления отключите пользователей/сделайте снапшот, а после — проверьте сеть и настоящий внешний IP клиента. Автоматическая диагностика при запуске приложения и fail-closed защита для *произвольно пересозданного* контейнера пока не реализованы.

Ограничения внешних облачных firewall, IPv6-политик на роутере и возможной блокировки UDP у провайдера остаются. Программа не отключает IPv6 вне VPN на пользовательских устройствах. Никаких приватных ключей, профилей, паролей и полных серверных конфигов не публикуйте в логах или issue.
