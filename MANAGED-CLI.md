# AWG Chain — managed AmneziaWG 3.1 (CLI-прототип)

**Ветка экспериментальная, текущую GUI-версию не меняет.**
Нативная цепочка AWG уже установлена и работает: на входном VPS активен
`awg-mediator`, на выходном `awg-destination`.

### Подключить Amnezia к работающей цепочке (рекомендуемый первый тест)

В PowerShell:

```powershell
git clone --branch experiment/managed-cli https://github.com/Abbygree11/AWG-Chain-Installer.git AWG-Chain-Managed-Test
cd AWG-Chain-Managed-Test
go run -mod=mod ./cmd/awg-managed-test -entry 45.88.177.100
```

Go 1.26+. При первом запуске Go скачает зависимости, **GUI и Fyne не компилируются**.

Нужен только SSH root-пароль входного VPS. Скрипт не меняет конфигурацию
действующего `awg-client`. Сначала проверяет `awg-mediator` и таблицу 100.
Требует свободных UDP 55424 и подсети Docker 172.28.66.0/24.

### Исправить UDP handshake на уже установленном контейнере

Если Amnezia находит `amnezia-awg2`, но подключение зависает и
`awg show awg0 latest-handshakes` выдаёт нули, возможна асимметрия
Docker DNAT (вход через `amn0 / eth1`, выход через `awc0 / eth0`).

В PowerShell с обновлённой веткой:

```powershell
git pull
go run -mod=mod ./cmd/awg-managed-test -entry 45.88.177.100 -repair-replies
```

CLI настраивает только правило для **исходящих UDP-пакетов с порта 55424**
внутри существующего контейнера: `ip rule ipproto udp sport 55424` и
отдельную таблицу `101` с маршрутом через `eth1`. Обычный исходящий
трафик клиентов по-прежнему направляется через `eth0`, который хост
перенаправляет через `awg-mediator`. Создание/удаление клиентов и
серверные ключи не затрагиваются. Текущие подключения не сбрасываются.
Правило сохраняется в `/opt/amnezia/start.sh` внутри контейнера
и в локальном шаблоне, используемом при его перезапуске. При полном
пересоздании контейнера официальным приложением нужно повторно проверить
маршрутизацию и работоспособность защиты от обхода.

**Подтверждение:** после исправления для нового подключения клиентом
с другого публичного IP проверь `docker exec amnezia-awg2 awg show awg0
latest-handshakes` и внешний IP (должен быть адрес Финляндии).
Команда `-repair-replies` пока не испытывалась отдельно на реальном VPS;
проверить её на экспериментальной машине перед переносом в GUI.

### С нуля на двух чистых VPS

```powershell
go run -mod=mod ./cmd/awg-managed-test -full -entry 45.88.177.100 -exit <IPv4-выходного-VPS>
```

Полная установка сначала использует проверенную нативную цепочку и затем
создаёт отдельный `amnezia-awg2`. Старый клиент сохраняется как резерв на
время эксперимента; **не используйте временный native .conf для друзей**.

### Что делает CLI

1. Устанавливает Docker из Ubuntu APT, создаёт выделенную Docker-сеть
   `awg-chain-managed` и совместимую с Amnezia `amnezia-dns-net`.
2. Получает официальный Dockerfile и `start.sh` Amnezia с зафиксированного
   commit `ac175c8a8147cfe56f98c8372ec17ea2ba00bb02` (ветка dev).
   Базовый образ Dockerfile — `amneziavpn/amneziawg-go:latest`; его digest
   **ещё не зафиксирован**.
3. Устанавливает контейнер с **именем `amnezia-awg2`** и UDP 55424.
   Генерирует ключи внутри контейнера, сохраняет конфигурацию в ожидаемых
   официальным клиентом путях `/opt/amnezia/awg/awg0.conf`,
   `wireguard_server_public_key.key`, `wireguard_psk.key`.
4. Создаёт persistent systemd-службу `awg-chain-managed-route`:
   PBR `fwmark 0x6601 → table 100 → awg-mediator`. Ответный UDP трафик с
   порта 55424 направляет обратно через входной VPS. Правило
   `DOCKER-USER` блокирует прямой выход клиентского трафика в интернет.
5. Сравнивает выходной публичный IPv4 контейнера с IPv4 при прямой
   проверке через `awg-mediator`. При несовпадении завершает работу ошибкой.

### Проверка в официальном приложении Amnezia VPN

Self-hosted → **Пропустить установку** → **Управление** →
**Проверить ранее установленные сервисы**. Ожидаем `amnezia-awg2`.
Далее создай тестового пользователя в официальном Amnezia VPN и проверь
его подключение и внешний IP из роутера/телефона.

**Важно:** распознавание контейнера и управление пользователями
предполагаются на основании исходников официального клиента, но **пока
не подтверждены реальным тестом**. Не давай друзьям доступ, пока
реальный Amnezia-клиент не обнаружит сервер и не создаст рабочий peer.

**Ограничения:** это лабораторная интеграция с Docker: обновление,
пересоздание или смена сети контейнера через официальный клиент может
нарушить статическую маршрутизацию. При этом трафик контейнера может
оказаться вне созданных правил — не рассчитывай на защиту от утечек
после обновления Amnezia до отдельной проверки. Не обновляй/recreate
контейнер на этапе теста.

Скрипт не перезаписывает обнаруженный `amnezia-awg2` и не
удаляет существующие VPN-конфигурации. При ошибке частичные изменения
на VPS могут остаться. VPS с действующим Docker-сервисом, сторонним
firewall или занятыми подсетями для этого прототипа не подходит.
